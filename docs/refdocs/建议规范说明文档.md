Mission-Critical Aviation Cockpit/Ops System

本项目应采用的核心 UI 规范：【Aero-Critical 航空关键态势设计规范】

建议本项目定义并执行一套融合民航人机工效学（FAA HF-STD-001 / ICAO Doc 9817）与现代军工战术数据终端（C2 / Telemetry HUD）的定制规范体系。其核心四大支柱如下：

```text
┌─────────────────────────────────────────────────────────────────┐
│            Aero-Critical 航空关键态势设计规范体系               │
├─────────────────┬─────────────────┬─────────────────┬───────────┤
│  1. 色度绝对垄断 │  2. 跑道几何锚点 │  3. 战术密集标尺 │ 4. 双模工效│
│  (Chromatic)    │  (Spatial HUD)  │  (High-Density) │  (Dual-Ops)│
└─────────────────┴─────────────────┴─────────────────┴───────────┘
```

1. 色度绝对垄断原则（Chromatic Monopolization）
* 色彩禁欲主义（Achromatic Base）：
  * 系统常规界面的背景、容器、边框、非警报状态文字全部限制在冷钛合金色系（Cold Slate / Graphite / Deep Obsidian）与微弱的战术青蓝（Tactical Cyan，只作为辅助对齐线与中性高亮）；
* 警示色彩的语义独占（ICAO 航空四级警戒编码）：
  * 🔴 CRITICAL / WARNING（严重风切变 / WSA / 降落禁止窗口）：国际航空红（#FF3B30 / #EF4444）。全系统只有“威胁飞行安全的失速临界事件”才有资格调用纯红及红色呼吸光晕；
  * 🟠 CAUTION / HAZARD（中度风切变 / 显著颠簸 / LLJA）：战术琥珀橙（#F59E0B / #FF9500）；
  * 🟡 ADVISORY / WATCH（轻度切变 / 阵风趋势 / 趋势观察）：警戒航行黄（#EAB308 / #FACC15）；
  * 🟢 NORMAL / ACTIVE（设备在线 / 通道通畅 / 气象静稳）：航空电子绿（#10B981 / #22C55E）。
* 物理气象色标与操作界面的严格隔离：
  * 雷达组合反射率（0~70 dBZ）必须忠实于国际通用气象雷达色标带（蓝-绿-黄-橙-红-紫-白）；操作按钮、筛选控件严禁使用这些颜色，防止被误判为气象回波中心。

1. 跑道几何空间为绝对视觉锚点（Runway-Centric Spatial HUD）
* 所有的切变核心区、激光径向风微下冲羽流、低空急流轴线，在视觉上必须永远锚定在 ZULS 跑道几何坐标系上；
* 进近航道延长线（09/27 号或 16L/34R 两端 3nm~5nm 下滑道）采用航空标图标准虚线，告警气泡直接投射在航径断面（Gate / Glide Path）相应距离刻度上，管制员一眼就能获知“在距跑道端多少公里、多少高度遭遇切变”。

1. 战术级信息密度与标尺网格（Tactical Dense Grid & Monospace Alignment）
* 微结构边框代替阴影：彻底舍弃 CSS 漫反射模糊投影（Drop Shadow），改用 `0.5px ~ 1px` 微发光刻度线（Precision Hairlines）、切角边框（Chamfered Corners）与暗色微透玻璃态（Backdrop-blur）；
* 全要素等宽排版（Tabular Numerics）：
   界面中所有的风速（m/s）、风向（°）、垂直气流速度、高度层（km）、UTC/地方时时间戳，必须强制开启 `font-variant-numeric: tabular-nums`，字体采用工程与航空电子领域推崇的等宽几何无衬线体（如 JetBrains Mono / DIN 1451 / Space Mono*），数值跃迁时绝不产生 1 像素的跳动；
* 微型信息胶囊（Micro-KPI & Telemetry Strips）：
  * 摒弃大块冗余卡片，采用紧凑的数据带（Data Ribbon），用极窄进度指示条与迷你状态灯（LED Dot）交代状态。

1. 场景双模态工效学适配（Dual-Operational Modes）
针对民航运行的两种典型物理照明环境，规范必须天生支持两种专属语义模态，而非简单的黑白反转：
1. 日间值班模式（Day Ops / 气象值班室）：
   * 底色：低反射中性冷灰（Technical Slate），而非刺眼的纯白；
   * 对比度：文字对比度严格维持在 WCAG AAA 级别，抗日光眩光。
2. 夜间 / 态势中枢模式（Night Ops & Command Big Screen / 进近管制厅 & 领导大屏）：
   * 底色：深海蓝黑（Obsidian Abyss，#060B14 ~ #0A101D）；
   * 光感控制：采用 HUD 荧光弱发光（Subtle Luminescence），控制整屏发光总光通量，避免在弱光暗室中对值班员视网膜造成暗适应剥夺（Night Adaptation Loss）。

---

四、落地行动建议（从当前原型向工业级演进）

如果基于上述规范体系对现有系统进行持续迭代，优先落地顺序应为：
1. 建立严苛的 Design Token（设计变量系统）：
   * 彻底清理代码中的任意色值，建立只包含 `surface`（底色）、`grid-line`（刻度）、`hud-cyan`（中性态势）以及被严格管制的 `alert-4-levels`（红/橙/黄/绿）语义变量；
2. 重构数据排版规范：
   * 将时序图、风速数值、经纬度、电文代码统一收敛为等宽字符体系；
3. 将普通管理表单升级为战术仪表板：
   * 如预警签发模块，弱化传统表单的“填空感”，强化“战术核准与分发闸门”的机械仪式感与确认保障。
